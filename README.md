## 🏢 О проекте

Приложение предназначено для учёта персональных финансовых потоков:
* Многопользовательская авторизация (логин/пароль с криптографическим солением и хэшированием SHA-256).
* Учёт доходов и расходов с разделением по категориям.
* Управление бюджетами категорий и отслеживание оставшегося лимита.
* Подсчёт статистики: общей, по категориям, по выбранному набору категорий и за произвольный временной период.
* Автоматические оповещения о превышении лимитов, достижении 80% порога бюджета, превышении расходов над доходами и отрицательном балансе.
* Сохранение состояния кошелька в файл при выходе и автоматическая загрузка при авторизации.
* Переводы между кошельками пользователей с фиксацией расхода у отправителя и дохода у получателя.
* Экспорт и импорт отчётов и снимков данных в форматах CSV, JSON и TXT.

## 🏗 Архитектура приложения

Проект построен в соответствии с принципами **Clean Architecture (Чистая архитектура)** и **SOLID**:

```
ru.promo.finance
├── domain/                    # Доменный слой (ядро бизнес-логики)
│   ├── model/                 # Модели: User, Wallet, Transaction, Budget, Alert, etc.
│   └── repository/            # Интерфейсы репозиториев (UserRepository, WalletRepository)
├── infrastructure/            # Инфраструктурный слой
│   ├── storage/               # Хранилище: InMemory-репозитории, FileStorageService, SimpleJson
│   └── export/                # Экспорт/импорт: ReportExporter (CSV, JSON, TXT)
├── service/                   # Слой сервисов (Use Cases)
│   ├── AuthService.java       # Регистрация, вход, выход, валидация учётных данных
│   ├── SecurityService.java   # Генерация соли, хэширование SHA-256 (1000 итераций)
│   ├── WalletService.java     # Доходы, расходы, переводы между пользователями
│   ├── BudgetService.java     # Установка, редактирование и расчёт бюджетов
│   ├── CategoryService.java   # Управление категориями (создание, переименование, удаление)
│   ├── AlertService.java      # Генерация оповещений по лимитам и балансу
│   └── StatisticsService.java # Расчёт финансовой сводки, фильтрация по датам и категориям
├── ui/                        # Пользовательский интерфейс
│   ├── ConsoleUI.java         # Командный цикл CLI, парсинг аргументов, обработка команд
│   └── TableFormatter.java    # Отрисовка красивых таблиц в терминале (Unicode/ASCII)
└── Main.java                  # Точка входа (DI-композиция, shutdown hooks)
```

### Модули и слои:
1. **Domain Models**:
   - `User`: учётная запись пользователя (id, логин, хэш пароля, соль, дата создания).
   - `Wallet`: кошелёк, привязанный к пользователю; хранит баланс, операции, бюджеты и категории.
   - `Transaction`: неизменяемая запись о доходе, расходе или переводе с использованием `BigDecimal` для исключения ошибок округления чисел с плавающей точкой.
   - `Budget` & `BudgetStatus`: лимит на категорию, вычисление израсходованного, остатка и перерасхода.
   - `Alert`: оповещения о превышении бюджета, предупреждения о пороге 80%, превышении расходов над доходами.
2. **Repositories (Storage)**:
   - Интерфейсы `UserRepository` и `WalletRepository`.
   - In-memory реализации на базе потокобезопасных коллекций (`ConcurrentHashMap`, `CopyOnWriteArrayList`).
   - `FileStorageService`: надёжное персистентное сохранение на диск с атомарной записью через временные файлы.
   - `SimpleJson`: встроенный легковесный JSON-парсер без внешних зависимостей.
3. **Services**:
   - Чёткое разделение ответственности. Каждый сервис решает свою изолированную задачу.
4. **UI Layer**:
   - Устойчивый цикл чтения команд, парсер аргументов с поддержкой кавычек (для категорий из нескольких слов, например `"Коммунальные услуги"`), подробные сообщения об ошибках и форматирование таблиц.

## 💻 Стек технологий и требования

- **Язык**: Java 25 (используются современные возможности: records, pattern matching, switch expressions, enhanced null-safety).
- **Сборка**: Apache Maven 3.9+ (совместимо с 3.8+).
- **Тестирование**: JUnit 5 Jupiter 5.11.4.
- **Внешние библиотеки**: проект не требует сторонних runtime-библиотек (работает автономно на стандартной библиотеке Java).

## 📖 Справочник команд CLI

### 1. До авторизации
| Команда | Описание | Пример |
|---|---|---|
| `register <логин> <пароль>` | Регистрация нового аккаунта | `register ivan secret123` |
| `login <логин> <пароль>` | Вход в систему (загружает кошелек с диска) | `login ivan secret123` |
| `help` | Справка по командам | `help` |
| `exit` | Завершение работы | `exit` |

### 2. Управление финансами (после авторизации)
| Команда | Описание | Пример |
|---|---|---|
| `income <категория> <сумма> [описание]` | Добавить доход | `income Зарплата 60000 "Октябрь"` |
| `expense <категория> <сумма> [описание]` | Добавить расход | `expense "Коммунальные услуги" 3000 "ЖКХ"` |
| `transfer <получатель> <сумма> [описание]` | Перевод другому пользователю | `transfer alex 1500 "За обед"` |

> [!TIP]
> Категории и описания, содержащие пробелы, можно заключать в кавычки, например: `"Коммунальные услуги"`.

### 3. Бюджеты
| Команда | Описание | Пример |
|---|---|---|
| `budget set <категория> <лимит>` | Установить лимит расходов на категорию | `budget set Еда 4000` |
| `budget edit <категория> <новый_лимит>` | Изменить существующий лимит | `budget edit Еда 4500` |

| `category delete <название>` | Удалить категорию | `category delete Такси` |

### 5. Отчёты и статистика
| Команда | Описание | Пример |
|---|---|---|

## 💸 Дополнительное задание: Переводы между пользователями

Реализована возможность безопасных переводов между кошельками:
* Идентификация отправителя и получателя по логину (`transfer <получатель> <сумма> [описание]`).
* У отправителя регистрируется расход типа `TRANSFER_OUT` по категории `Перевод`.
* У получателя регистрируется доход типа `TRANSFER_IN` по категории `Перевод`.
* Валидация:
  - Проверка достаточности средств у отправителя.
  - Запрет перевода самому себе.
  - Проверка существования получателя в системе.
  - Сохранение кошельков обоих пользователей.

## 🔔 Система оповещений (Alerts)

Приложение отслеживает финансовые события и предупреждает пользователя:
1. **Превышение лимита бюджета по категории**: когда фактические траты превышают установленный лимит (остаток бюджета становится отрицательным).
2. **Предупреждение о приближении к лимиту (>=80%)**: когда потрачено от 80% до 100% бюджета.
3. **Превышение расходов над доходами**: если суммарные расходы пользователя превысили суммарные доходы.
4. **Отрицательный баланс**: предупреждение, если баланс опустился ниже нуля.
5. **Нулевой баланс**: предупреждение при обнулении средств.

## 💾 Сохранение и загрузка данных

* Все рабочие данные во время работы хранятся в оперативной памяти (in-memory) для максимальной производительности.
* При выходе из приложения (`exit`, `logout`, а также через аварийный JVM Shutdown Hook) кошелёк пользователя сохраняется в файл `data/wallet_<login>.json`.
* Список зарегистрированных пользователей сохраняется в `data/users.json`.
* При авторизации (`login`) данные кошелька автоматически считываются с диска.

## 🧪 Тестирование

Проект содержит развитый набор из **42 автоматических тестов** (Unit- и интеграционные тесты):

1. **`UserAndAuthTest` (8 тестов)**: регистрация, валидация логина и пароля, защита от дубликатов, вход, проверка неверного пароля, соление и криптостойкое хэширование.
2. **`TransactionAndWalletTest` (6 тестов)**: создание доходов и расходов, проверка баланса, валидация отрицательных сумм и пустых категорий, сложные цепочки операций.
3. **`CategoryAndBudgetTest` (8 тестов)**: добавление, каскадное переименование с обновлением всех прошлых транзакций, удаление категорий, установка и изменение бюджетов.
4. **`AlertServiceTest` (5 тестов)**: срабатывание предупреждений при перерасходе, 80% пороге, дефиците бюджета и падении баланса.
5. **`StatisticsServiceTest` (4 теста)**: точное совпадение с примером из ТЗ, фильтрация по выборке категорий, уведомления о неизвестных категориях, фильтрация по датам.
6. **`TransferServiceTest` (5 тестов)**: успешный перевод, проверка балансов обоих участников, недостаток средств, перевод самому себе, несуществующий адресат.
7. **`PersistenceAndExportTest` (4 теста)**: запись и чтение пользователей и кошелька с диска, экспорт/импорт CSV и JSON.
8. **`ConsoleUIIntegrationTest` (2 теста)**: сквозная симуляция командной сессии CLI (ввод через stdin, верификация форматированного вывода).

Для запуска тестов выполните:
```bash
./test.sh
# или через Maven:
mvn test
```

## 🤖 CI/CD автоматизация

В репозитории настроен пайплайн **GitHub Actions** (`.github/workflows/ci.yml`), который при каждом пуше и Pull Request в ветки `main`/`master`:
- Настраивает окружение JDK 25;
- Выполняет чистую сборку и запуск всех тестов (`mvn clean verify`);
- Архивирует готовый JAR-артефакт сборки.
